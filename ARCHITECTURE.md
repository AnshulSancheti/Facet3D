# Architecture — face_edge_snake_v2

The model uses six cube charts: face/row/column. CubeTopology transports body headings over seams and maps cells to 3D. PuzzleRules computes a straight exit lane on the head's face; the lane ends at its boundary and never folds. Cells are ordered tail-to-head, and `head_direction` is shown by the final chevron; the last cell may contain a rounded quarter turn. Stored `route` fields are explicitly rejected.

Only occupied body cells and the head's newly entered exit cells form a move's swept footprint. The trailing body follows its own vacated cells. Validation forbids body overlaps, invalid seams, self-intersections and exit lanes crossing their own body. Thus new external collisions can only occur in the computed head lane. Other faces matter only when a wrapped piece occupies that lane. Locks add removal prerequisites. Pieces only disappear and keys only unlock: dependencies are static and monotone.

CompiledBoard builds indexed occupancy, blockers and key prerequisites once. Kahn's algorithm solves the complete monotone graph and detects cycles/depth. PuzzleSolver also retains state-budgeted/time-budgeted DFS with memoization for independent checks. Invalid definitions, exhausted budgets and proved deadlocks have distinct statuses. Rules.replay_solution independently updates occupancy and rechecks every move without using the compiled graph.

LevelGenerator uses a versioned integer PRNG. Reverse insertion requires each new arrow's head lane to be clear of every previously placed piece. It grows the body backward through empty cells, including occasional seam transitions. Tail extensions may only block earlier-inserted arrows, preserving reverse insertion as a constructive solution. After packing, a deterministic orientation pass evaluates both endpoints and all non-self-crossing head directions. It schedules actual legal removals while favoring the deepest cleared blocker ancestry, then assigns key/lock pairs in that proven order. Acceptance caps opening moves and requires tier-specific dependency depth. Geometry, density, shape/wrap quotas and independent occupancy replay are checked before accepting a level. The 100 campaign definitions are generated offline. Daily generation uses fixed operation budgets on a worker thread; no elapsed-time decisions affect content. A deterministic validated 25×25 fallback is marked with source and failure metadata. Runtime timing is excluded from daily definitions.

PuzzleView combines the flat strokes of each arrow into one mesh on a cached sharp ceramic cube with flat face normals and an inset contrast rim. There are no exit guides. Static selection uses one cube physics body, local face/grid conversion, and the occupancy index. Removing/undoing changes only that arrow plus lock colors. Moving flat quads follow rounded body samples then a tangent extension off the head face. Generation tokens, bound tweens and finite timers make restart/cancellation safe.

The 3D scene renders into a transparent SubViewport in the HUD-free central area. Camera fit frames the cube overview; a narrower field of view provides 1–3× zoom without moving the camera inside the cube. One-finger drag rotates; two-finger pinch suppresses taps/rotation until all fingers release. Screen/viewport coordinate helpers keep physics picking aligned under resizing and zoom.

Game owns UI, removed-ID history, compiled state, thread result adoption/cancellation, hints and original definitions. Daily completion never changes campaign progress. SaveStore schema 2 archives original schema-1 bytes before migration, starts the new campaign at 1, carries hints/preferences, atomically replaces saves and recovers backups. Daily keys include the ruleset. Events are local and bounded. A debug-only probe writes at most 12 local performance windows; it is absent in release builds.

AdsService remains a disabled-by-default facade. Native SDK access, UMP and reward deduplication are unchanged. No external analytics or backend is required.
